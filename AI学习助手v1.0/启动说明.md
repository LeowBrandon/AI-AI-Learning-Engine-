# 启动说明

「AI 学习助手」的完整启动指南。第一次接触这个项目的人，按本文档操作即可跑起来。

---

## 一、这个项目是什么

一个把课程资料变成可对话、可自测、可追踪的学习工具。前端是纯 HTML/CSS/JS 的静态页面，
后端是 Python Flask 服务，资料内容与大模型能力都在后端。

功能：**传资料 → 聊资料 → 做测评 → 看进度 → 出周报**。

---

## 二、环境要求

| 需要什么 | 版本 | 说明 |
|---|---|---|
| **Python** | 3.10 以上 | 后端必需。前端只借用它自带的静态文件服务 |
| **浏览器** | 任意现代浏览器 | Chrome / Edge / Firefox / Safari 均可 |
| **大模型 API Key** | — | 可选。不填也能启动，但聊天、出题、改卷、周报四个功能会报错 |

**Windows 安装 Python 时务必勾选 `Add Python to PATH`**，否则命令行里找不到 `python`。

## 四、最快启动方式（推荐）

### 怎么运行这两个文件

**必须在 Windows 资源管理器里双击，不能在编辑器或预览窗口里点。**

1. 按 `Win + E` 打开资源管理器
2. 找到本项目文件夹（和 `start_backend.bat` 同一层）
3. **双击 `start_backend.bat`** —— 会弹出一个黑色命令行窗口，后端在里面运行
4. 等它显示 `Running on http://127.0.0.1:8765`，再**双击 `start_frontend.bat`**
5. 浏览器会自动打开应用

> 如果在 WorkBuddy 的文件列表里点这两个文件，只会打开它们的**源码预览**，
> 不会执行 —— 那看起来就像「点了没反应」。请到资源管理器里双击。

### Windows

```
双击 start_backend.bat   →  后端窗口保持打开，不要关
双击 start_frontend.bat  →  浏览器自动打开应用
```

### macOS / Linux

```bash
# 终端 1 —— 后端
bash start_backend.sh

# 终端 2 —— 前端
bash start_frontend.sh
```

脚本会自动完成：**创建虚拟环境 → 安装依赖 → 启动服务 → 打开页面**。
首次运行需要下载依赖，可能要等一两分钟；之后再启动就很快了。

**后端窗口要一直开着**，关掉窗口就等于停止后端。

> **页面右上角的圆点**：绿色 = 后端已连接，红色 = 连不上。
> 如果先开的前端后开的后端，页面会显示红点，**最多等 8 秒会自动变绿**
> （页面每 8 秒重新检测一次）。

## 五、手动启动（想自己控制每一步时用）

### 第 1 步：配置后端

进入 `backend` 目录，把配置模板复制成实际配置：

```bash
cd backend

# Windows
copy .env.example .env

# macOS / Linux
cp .env.example .env
```

用文本编辑器打开 `backend/.env`，**至少填上大模型的 API Key**：

```ini
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-你的密钥
LLM_MODEL=deepseek-flash
```

**这三项互相独立，可以指向任意 OpenAI 兼容的服务**，换服务商只改这里，代码一行不用动。

其余配置项都有合理默认值，不用动：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `PORT` | 8765 | 后端监听端口 |
| `APP_ENV` | development | 开发模式，改代码自动重载 |
| `DATABASE_URL` | SQLite | 默认 `backend/instance/app.db`，可换 PostgreSQL / MySQL |
| `MAX_UPLOAD_MB` | 200 | 单个上传文件大小上限（MB）。改这里记得同步改 `frontend/js/api.js` 的 `MAX_UPLOAD_MB`（前端会先拦一道） |
| `LLM_TIMEOUT` | 90 | 单次调用大模型的超时（秒） |
| `LLM_MAX_RETRIES` | 3 | 调用失败后的重试次数（总尝试 = 1 + 这个值） |
| `CHUNK_SIZE` | 1200 | 资料切片长度（字符） |
| `MATERIAL_CONTEXT_LIMIT` | 24000 | 单次请求最多拼多少字符的资料正文给模型 |
| `LLM_MAX_RETRIES` | 3 | 调用失败后的重试次数 |
| `LLM_TEMPERATURE` | 0.3 | 模型温度 |

> **不填 `LLM_API_KEY` 会怎样**：服务照常启动，上传、看资料、看进度都正常；
> 但聊天、出题、改卷、周报会返回「未配置 LLM_API_KEY」的提示。

### 第 2 步：启动后端

```bash
# 还在 backend 目录下

# Windows
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe scripts\init_db.py
.venv\Scripts\python.exe app.py

# macOS / Linux
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/init_db.py
.venv/bin/python app.py
```

看到这样的输出就成功了：

```
 * Running on http://127.0.0.1:8765
```

**关于建表**：`scripts/init_db.py` 会创建 8 张表，已存在的表不动。
想清空重来加 `--drop`：`python scripts/init_db.py --drop`。
（首次启动其实会自动建表，这一步主要是为了看清楚建了哪些表。）

**验证后端是否正常**：浏览器打开 <http://127.0.0.1:8765/api/health>，
应该看到 `{"status": "ok"}`。

### 第 3 步：打开前端

前端是**纯静态页面，没有构建步骤**，直接用浏览器打开就行：

```
双击 frontend/index.html
```

就这样，不需要起服务。后端已经允许跨域，实测 `file://` 页面能正常调接口。

> 如果你更习惯用 HTTP 服务打开（比如要在手机上访问），也可以：
> ```bash
> cd frontend
> python -m http.server 5500     # 然后访问 http://127.0.0.1:5500
> ```

## 六、端口说明

只有**后端**需要端口：

| 服务 | 端口 | 改法 |
|---|---|---|
| 后端 | 8765 | 改 `backend/.env` 里的 `PORT` |
| 前端 | 不需要端口 | 直接打开 `frontend/index.html` 即可 |

**为什么后端不用 8000**：8000 太常被别的程序占用（本机上就被一个系统服务常驻占用，
导致后端根本起不来）。8765 冲突概率低得多。

如果改了后端端口，前端的 `frontend/js/api.js` 里的 `BASE_URL` 要跟着改。
不想改代码的话，可以在页面地址后加参数临时覆盖：

```
http://127.0.0.1:5500/?api=http://127.0.0.1:9000/api
```

> 用 `file://` 打开时这个参数不好加，改端口就直接改 `api.js` 里的 `BASE_URL`。

## 七、常见问题

**Q：双击 `start_backend.bat` / `start_frontend.bat` 没反应、没打开网页**
两种可能，先确认第一种：

1. **你是在编辑器或预览窗口里点的** —— 那样只会看到文件源码，不会执行。
   请按 `Win + E` 打开**资源管理器**，找到项目文件夹，在那里双击。
2. **真的执行了但出错** —— 脚本已经改成**任何失败都会停下来并提示**，
   窗口不会一闪而过。把窗口里的文字发我即可定位。

**Q：点了 `start_backend.bat`，窗口里说端口被占用**
8765 已经被别的程序（可能是上一次没关掉的后端）占着。
关掉那个窗口，或改 `backend/.env` 里的 `PORT`，
同时把前端 `frontend/js/api.js` 里的 `BASE_URL` 改成同一个端口。

**Q：上传文件提示「超过 200 MB 上限」**
单个文件上限是 200 MB。要调整的话改 `backend/.env` 里的 `MAX_UPLOAD_MB`，
同时把 `frontend/js/api.js` 里的 `MAX_UPLOAD_MB` 改成同一个数字（前端会先拦一道，
两边不一致时前端可能拦不住或拦错）。

**Q：生成测试题 / 周报时提示「请求超时」**
说明这一次模型响应特别慢，或者网络抖动、后端正在重试。
**直接再点一次就行**，不用做别的。前端给走大模型的请求留了 240 秒，
正常情况远远够用；真超时了说明这次确实异常。

> 如果你看到的是 `signal is aborted without reason` 这种看不懂的报错，
> 那是旧版本的问题（前端超时只有 15 秒），已经修好了 —— 更新一下前端文件即可。

**Q：出题总是失败**
先看后端窗口的日志。常见原因是：
- 资料还没解析完（状态不是「完成」）—— 等一会儿或点「重试」
- `LLM_API_KEY` 没填或额度用完 —— 后端会返回明确的原因
- 资料内容太少，出不出这么多题 —— 少选几道题，或多传几份资料

**Q：启动脚本报「找不到 python 命令」**
Windows 装 Python 时没勾 `Add Python to PATH`。重装一次并勾上，或手动把 Python 目录加进 PATH。
脚本里已经写了兜底：`python` 找不到时会依次尝试 `py -3` 和常见的安装目录
（`%LOCALAPPDATA%\Programs\Python\Python313` 等）。

**Q：后端窗口一闪就没了**
说明启动过程中出错了。现在的脚本在出错时会 `pause` 等你看，
如果还是闪退，说明是更底层的问题（比如 Windows 拦截了脚本执行）。
这种情况下改用「五、手动启动」里的命令逐条执行，能看到完整的报错。

**Q：`.bat` 窗口里的中文是乱码**
脚本开头已经执行了 `chcp 65001` 把控制台切成 UTF-8，绝大多数情况正常。
个别老版本 Windows 仍可能显示乱码 —— **不影响功能**，脚本照常执行。
看不懂提示的话对照本文档的说明即可。

**Q：页面右上角的圆点是红色的**
后端没启动，或者端口对不上。先确认 <http://127.0.0.1:8765/api/health> 能打开。
绿点 = 后端已连接，红点 = 连不上。

**Q：上传资料后一直显示「解析中」**
解析在后台线程里跑，通常几秒就好。如果一直是解析中，说明解析出错了 ——
在「资料库」页面点该资料的「重试」，或看后端窗口的日志。

**Q：聊天/出题时报「未配置 LLM_API_KEY」**
`backend/.env` 里的 `LLM_API_KEY` 没填。填好后**重启后端**。

**Q：聊天回答「这份资料里没有提到这个问题」**
这是正常行为 —— 工具被设计成只依据你上传的资料回答，资料里没有的就不编。
换个问法，或上传包含该内容的资料。

**Q：上传 `.doc` / `.ppt` 被拒绝**
旧版 Office 二进制格式没有可靠的解析器。请用 Word / PowerPoint 另存为 `.docx` / `.pptx` 再上传。

**Q：端口被占用**
换个端口。后端改 `backend/.env` 的 `PORT`，前端启动时传参 `python -m http.server 6000`。

**Q：想清空所有数据重来**
删掉 `backend/instance/` 整个目录，重新运行 `python scripts/init_db.py`。
注意：这会删掉数据库和已上传的文件。

## 八、启动后怎么用

1. 打开「**资料库**」→ 拖入 PDF / PPTX / DOCX / MD / TXT 文件，等状态变成「完成」
2. 打开「**学习**」→ 顶部下拉框选一份资料，就资料内容提问
3. 打开「**测评**」→ 选资料和题量，点「开始测试」，做完提交看结果
4. 打开「**进度**」→ 看知识点掌握度雷达图，可以给每份资料写笔记（自动保存）
5. 打开「**报告**」→ 选日期范围生成周报，可下载成 `.md` 文件
